## Daily Editing Rules

### 1. Keep it event-first, not opinion-first
- Do not lead with editorial judgments.
- Prefer "发生了什么" over "为什么它很重要".
- Use short factual summaries such as:
  - 发布了什么
  - 更新了什么
  - 修复了什么
  - 社区在讨论什么
- Avoid turning every line into interpretation.

### 2. `全球 AI 行业热点` should be factual and compact
- Pick the most visible 3-5 events in the active daily window.
- Prefer direct event descriptions.
- If a story also appears in a vendor section, keep the global summary shorter rather than more interpretive.

### 3. `模型厂商动态` should classify, not force commentary
- Check these buckets in order:
  - `OpenAI`
  - `Anthropic`
  - `Gemini`
  - `Open Source`
- Only include buckets with actual daily items.
- If a bucket has no strong item in the window, omit it or add one brief factual note such as "今日无新增高信号官方更新".

### 4. `AI 智能体 / 工作流` should list concrete project movement
- Prefer release, feature, workflow, infra, and toolchain events.
- Good fits include OpenClaw, n8n, Claude Code workflow discussion, coding-agent infra, and adjacent developer automation.
- Summaries should describe the update itself, not over-explain its strategic meaning.

### 5. `开源社区动态` should surface counts and interaction
- Keep `GitHub Releases` factual.
- For `Community Picks`, always include:
  - subreddit
  - score
  - num_comments
- Sort by `score` desc, then `num_comments` desc.
- Max 5 unique posts per subreddit.

### 6. Statistics should be visible
- Show overall source counts in the footer.
- Prefer section counts in headers when available.
- For multi-source stories, show the number of merged sources.
- For Reddit, always show interaction metrics.

## Formatting Rules
- Keep emoji headers exactly as anchors.
- Use Discord-safe links with `<...>`.
- Use `🔥score` for editorial/news sections.
- Do not add long narrative paragraphs under every section.
- Daily should feel like a classified event digest, not a mini essay.

## Why This Daily Template
- Keeps daily output quick to scan.
- Reduces subjective over-writing.
- Preserves category structure while borrowing Discord's concise style.
- Makes the statistics layer explicit for both operators and readers.
